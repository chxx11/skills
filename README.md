# CX Skills

一组面向 Codex、Claude Code 和其他 AI Agent 的个人技能。

这些技能关注两个高频问题：让 Agent 更敢于追问关键细节，以及让提示词更短、更准、更可执行。它们保持轻量、可组合、易修改，适合放进自己的 Agent 工作流里长期使用。

## 快速开始

使用 `skills` 安装：

```bash
npx skills@latest add chxx11/skills
```

安装时选择需要的技能和目标 Agent。安装完成后，在对应 Agent 中按技能说明触发使用。

## 为什么写这些技能

AI Agent 的能力很强，但常见问题并不复杂：需求没有问透，提示词写得太满，决策过程缺少记录，输出看起来完整却没有抓住主要矛盾。

这个仓库里的技能用于修正这些问题。

### 1. 方案需要被追问

很多方案在落地前看起来成立，细节一展开就会暴露风险。`cx-dig-deeper` 要求 Agent 先建立分析框架，再用少量高价值选择题推动用户决策，并把共识记录到文件中。

适合场景：

- 评审一个产品方案、技术方案或执行计划
- 在动手前压测假设、风险和边界条件
- 把模糊想法整理成可判断、可推进的决策记录

### 2. 提示词需要降噪

很多提示词把篇幅浪费在 Agent 默认会做的事上，例如“认真思考”“全面分析”“高质量输出”。`cx-no-fluff` 要求只保留会改变执行结果的增量信息。

适合场景：

- 给另一个高能力 Agent 写任务提示词
- 压缩冗长需求，保留关键约束和上下文
- 删除空泛要求，提高提示词的信息密度

## 设计原则

- **小而明确**：每个技能只解决一个具体问题。
- **可执行**：技能必须给出明确动作，而不只描述价值观。
- **可记录**：涉及决策的过程要沉淀到文件中，便于复盘和继续推进。
- **少废话**：减少套话、泛化要求和不会改变结果的文本。
- **可修改**：技能文件就是 Markdown，可以按个人工作流继续调整。

## 使用建议

先把技能安装到常用 Agent，再在真实任务中逐步调整措辞。技能文件不需要保持通用，越贴近自己的工作流，实际收益越高。

建议优先在以下任务中使用：

- 复杂决策前，使用 `cx-dig-deeper`
- 给子 Agent、自动化流程或新会话写提示词时，使用 `cx-no-fluff`
